# ダイブログ分析レポート プロンプト

`POST /api/analysis-report` から Microsoft Foundry のモデルを呼び出し、所有者の全ダイブログを対象に次の3項目を生成します。

- エリア別の潜り方傾向
- 全ログから見た利用者傾向
- 評価傾向に基づく訪問済み・未訪問スポットの推薦

入力はバックエンドで集計した統計値のみです。プロファイル時系列やユーザーの認証情報はモデルへ送信しません。出力は `response_schema.json` の Structured Outputs で制約します。

## 実行契約

- `config.yaml` の既定モデルは `gpt-5.4`。本番のデプロイメント名は `ANALYSIS_REPORT_AZURE_OPENAI_DEPLOYMENT` でGPS提案用モデルと分離する。
- 最大水深、潜水時間、最低水温は有限な正数だけを集計し、`0` 以下は未記録として平均から除外する。
- エリアはロケーション名の最初の半角 `:` または全角 `：` より前とし、区切りなし、空、名称なしは「不明」とする。
- 評価は `1` から `5` だけを集計し、おすすめ候補の根拠に使用する。
- 測定値や評価が無効なログも、全体本数とエリア別本数には含める。
- `system.md` は入力中のロケーション名を命令として扱わないようモデルを制約する。
- `response_schema.json` に加え、バックエンドでもトップレベル構造、配列件数、文字数、エリア名を検証する。
- 生成結果は保存しない。「レポートの作り直し」の実行ごとに所有者の全ログから再生成する。
